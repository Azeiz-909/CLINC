# عيادة تـحـدث — تنظيم المراجعين

نسخة كاملة بقاعدة بيانات حقيقية (Supabase) + تسجيل دخول بحسابات وكلمات مرور، تعمل من أي جهاز (جوال، لابتوب، أي مكان) وتُزامن البيانات تلقائيًا بين الجميع.

## ⚠️ تغيّر مهم عن النسخة السابقة

هذه النسخة **لم تعد تعمل بالاعتماد على GitHub Pages وحدها**، لأنها تحتاج جزءًا صغيرًا يعمل من جهة الخادم (لإنشاء الحسابات بأمان). لذلك:

- **يجب نشر الموقع بالكامل على Vercel** (وليس GitHub Pages) — Vercel يدعم كلًا من الواجهة والدوال الخادمية معًا.
- يمكنك الاستمرار في الاحتفاظ بالكود على GitHub (هذا مفيد وموصى به)، لكن **Vercel هو من يستضيف الموقع فعليًا**، وليس GitHub Pages.
- قاعدة البيانات نفسها مستضافة مجانًا على **Supabase** (خدمة منفصلة، لا علاقة لها بـ GitHub أو Vercel).

---

## الفكرة العامة (٣ خدمات مجانية تعمل معًا)

| الخدمة | الدور |
|---|---|
| **Supabase** | قاعدة البيانات الحقيقية (المراجعين، التصنيفات، الحسابات) + نظام تسجيل الدخول |
| **GitHub** | مكان حفظ الكود (اختياري لكن موصى به) |
| **Vercel** | يستضيف الموقع نفسه + دوال صغيرة لإدارة الحسابات (إضافة/حذف/إعادة تعيين كلمة مرور) |

---

## الملفات المرفقة

```
index.html            → الموقع بالكامل (الواجهة)
sql/schema.sql         → أوامر إنشاء الجداول — تُشغَّل مرة واحدة داخل Supabase
api/create-user.js     → دالة خادم: إنشاء حساب جديد (المدير فقط)
api/reset-password.js  → دالة خادم: إعادة تعيين كلمة مرور حساب (المدير فقط)
api/delete-user.js     → دالة خادم: حذف حساب (المدير فقط)
package.json           → يخبر Vercel بالمكتبة المطلوبة لدوال الخادم
.env.example           → مثال لأسماء متغيرات البيئة المطلوبة (بدون قيم حقيقية)
.gitignore
```

---

## الخطوة ١ — إنشاء قاعدة البيانات على Supabase

1. اذهب إلى [supabase.com](https://supabase.com) وأنشئ حسابًا (يمكن عبر GitHub مباشرة).
2. اضغط **New Project**. اختر اسمًا (مثلاً `clinic-app`) وكلمة مرور لقاعدة البيانات (احفظها في مكان آمن) والمنطقة الأقرب لك، ثم **Create new project**. انتظر دقيقة حتى يجهز المشروع.
3. من القائمة الجانبية اختر **SQL Editor** ثم **New query**.
4. افتح ملف `sql/schema.sql` المرفق، انسخ محتواه بالكامل، والصقه في المحرر، ثم اضغط **Run**. هذا ينشئ الجداول الثلاثة (الحسابات، التصنيفات، المراجعين) بكل الحماية اللازمة دفعة واحدة.
5. من القائمة الجانبية اذهب إلى **Settings → API**. ستحتاج ثلاث قيم من هذه الصفحة:
   - **Project URL** (مثل `https://xxxxx.supabase.co`)
   - **anon public key** (مفتاح طويل يبدأ بـ `eyJ...`)
   - **service_role secret key** (مفتاح آخر أطول، **سرّي جدًا** — لا تشاركه ولا تضعه في أي كود يعمل بالمتصفح)

## الخطوة ٢ — إنشاء أول حساب (حساب الدكتور الرئيسي)

بما أن إنشاء الحسابات لاحقًا يتم من داخل الموقع، أول حساب فقط يُنشأ يدويًا من لوحة Supabase:

1. من القائمة الجانبية اذهب إلى **Authentication → Users**.
2. اضغط **Add user → Create new user**.
3. **Email:** اكتب أي بريد وهمي بصيغة صحيحة، مثل `sara@clinic.internal` (لن يُرسَل له أي بريد فعلي).
4. **Password:** اختر كلمة المرور الحقيقية التي سيستخدمها الدكتور دائمًا.
5. فعّل خيار **Auto Confirm User** إن ظهر (حتى لا ينتظر تأكيدًا بالبريد).
6. اضغط **Create user**. بعد إنشائه، افتح المستخدم من القائمة وانسخ الـ **User UID** الخاص به (سلسلة طويلة تشبه `a1b2c3d4-...`).
7. ارجع إلى **SQL Editor → New query** وشغّل الأمر التالي بعد استبدال القيم:

```sql
insert into profiles (id, username, name, role, must_change_password)
values ('الصق-الـ-UID-هنا', 'sara', 'د. سارة', 'admin', false);
```

- `username`: هو ما سيكتبه الدكتور في خانة "اسم المستخدم" عند الدخول (حروف إنجليزية، بدون مسافات).
- `name`: الاسم الذي سيظهر داخل الموقع.
- `role`: اتركها `'admin'` لهذا الحساب فقط — فهو الوحيد الذي يستطيع إضافة/حذف حسابات الموظفين لاحقًا.
- `must_change_password`: `false` لأن الدكتور اختار كلمة مروره بنفسه في الخطوة ٤.

هذا الحساب أصبح جاهزًا للدخول مباشرة بـ (`sara` + كلمة المرور التي اخترتها).

## الخطوة ٣ — ربط الموقع بمشروع Supabase

1. افتح ملف `index.html` (بأي محرر نصوص، أو مباشرة من GitHub لاحقًا).
2. ابحث عن هذين السطرين قرب بداية الكود:

```js
const SUPABASE_URL = "https://YOUR-PROJECT.supabase.co";
const SUPABASE_ANON_KEY = "YOUR-ANON-PUBLIC-KEY";
```

3. استبدل القيمتين بـ **Project URL** و **anon public key** اللذين نسختهما في الخطوة ١ (وليس مفتاح service_role — هذا الأخير للخادم فقط ولا يوضع هنا إطلاقًا).
4. احفظ الملف.

---

## الخطوة ٤ — رفع المشروع على GitHub (موصى به)

1. أنشئ مستودعًا جديدًا في [github.com](https://github.com) (مثلاً `clinic-app`)، اجعله **Public** أو **Private** (كلاهما يعمل مع Vercel).
2. ارفع كل الملفات المرفقة (`index.html`, `sql/`, `api/`, `package.json`, `.env.example`, `.gitignore`) بنفس هيكلها — يمكنك سحبها وإفلاتها جميعًا دفعة واحدة في صفحة "Add file → Upload files"، مع الحفاظ على المجلدين `sql` و `api` كما هما.
3. اكتب رسالة Commit ثم اضغط **Commit changes**.

> **تنبيه:** لا ترفع مفتاح service_role في أي ملف على GitHub أبدًا. الملف `.env.example` لا يحتوي قيمًا حقيقية — القيم الحقيقية توضع لاحقًا في إعدادات Vercel فقط (الخطوة القادمة).

---

## الخطوة ٥ — النشر على Vercel

1. اذهب إلى [vercel.com](https://vercel.com) وسجّل الدخول بحساب GitHub.
2. اضغط **Add New → Project** واختر مستودع `clinic-app` ثم **Import**.
3. **قبل الضغط على Deploy**، افتح قسم **Environment Variables** وأضف المتغيّرين التاليين (القيم من الخطوة ١):

   | Name | Value |
   |---|---|
   | `SUPABASE_URL` | رابط مشروعك في Supabase |
   | `SUPABASE_SERVICE_ROLE_KEY` | مفتاح service_role السرّي |

4. اضغط **Deploy** وانتظر ثوانٍ. سيظهر رابط الموقع بالشكل: `https://clinic-app.vercel.app`
5. افتح الرابط وجرّب تسجيل الدخول بحساب الدكتور الذي أنشأته في الخطوة ٢.

**للتحديث لاحقًا:** أي تعديل ترفعه على مستودع GitHub يُنشر تلقائيًا على Vercel خلال ثوانٍ.

## كيف تُضاف حسابات جديدة للموظفين

1. سجّل الدخول بحساب الدكتور (المدير).
2. اضغط أيقونة ⚙️ (الإعدادات) أعلى الصفحة.
3. في قسم **"إدارة الحسابات"** أسفل النافذة، أدخل اسم مستخدم (إنجليزي) واسمًا معروضًا للموظف الجديد، ثم اضغط **إنشاء حساب جديد**.
4. سيظهر لك اسم المستخدم وكلمة مرور مؤقتة — انسخهما وشاركهما مع الموظف (عبر واتساب أو مباشرة).
5. عند أول دخول للموظف بهذه البيانات، سيُطلب منه تلقائيًا تعيين كلمة مرور خاصة به قبل الدخول لباقي الموقع — كلمة المرور المؤقتة تصبح غير صالحة بعدها.
6. من نفس القسم يمكن للمدير لاحقًا: **إعادة تعيين كلمة مرور** أي حساب (تولّد كودًا مؤقتًا جديدًا بنفس الطريقة)، أو **حذف الحساب** نهائيًا.

كل الحسابات (المدير والموظفين) ترى نفس بيانات المراجعين والتصنيفات — النظام مُصمَّم كنظام عيادة مشترك وليس بيانات منفصلة لكل موظف.

## تحويل الموقع إلى تطبيق على الجوال عبر Safari (iPhone / iPad)

1. افتح رابط الموقع (`https://clinic-app.vercel.app`) في **متصفح Safari** تحديدًا.
2. اضغط زر **المشاركة** (المربع وبداخله سهم للأعلى ⬆️) في شريط الأدوات السفلي.
3. مرّر لأسفل واختر **"Add to Home Screen" / "إضافة إلى الشاشة الرئيسية"**.
4. عدّل الاسم إن رغبت ثم اضغط **إضافة/Add**.
5. ستظهر أيقونة الموقع على الشاشة الرئيسية مثل أي تطبيق عادي، وتفتح بملء الشاشة بدون شريط المتصفح.

**لأجهزة أندرويد (Chrome):** افتح الرابط في Chrome، اضغط قائمة النقاط الثلاث (⋮)، ثم **"تثبيت التطبيق" / "Install app"**.

بما أن البيانات الآن على خادم حقيقي (وليست محفوظة محليًا في المتصفح)، الدخول من الجوال أو اللابتوب أو أي جهاز آخر بنفس الحساب يعرض نفس بيانات المراجعين فورًا ومتزامنة بينهما.

## ملاحظات أمان وخصوصية

- كل من يملك حسابًا (مدير أو موظف) يرى **كل** المراجعين — لا يوجد فصل بيانات بين الموظفين في هذا الإصدار.
- كلمات المرور لا تُخزَّن كنص واضح — Supabase يتولى تشفيرها بالكامل عبر نظام المصادقة الخاص به.
- مفتاح `service_role` هو المفتاح الوحيد الحساس في هذا المشروع — يبقى فقط داخل إعدادات Vercel (Environment Variables) ولا يظهر أبدًا في أي كود يصل إلى المتصفح.
- يُنصح لاحقًا، إذا رغبت، بإضافة تسجيل نشاط (من عدّل ماذا ومتى) أو صلاحيات أدق بين الموظفين — أخبرني إن احتجت ذلك.

## أسئلة متوقعة

**هل ما زلت أحتاج GitHub؟**
غير إلزامي تقنيًا (يمكن رفع الملفات مباشرة إلى Vercel دون Git)، لكنه موصى به لتسهيل التحديثات المستقبلية وتتبع التغييرات.

**ماذا لو نسيت كلمة مرور حساب الدكتور نفسه؟**
بما أنه لا يوجد حساب "مدير أعلى" فوقه من داخل الموقع، أعِد تعيينها من **Supabase Dashboard → Authentication → Users**، اختر الحساب، ثم **Reset password** مباشرة من هناك.

**هل هناك حد لعدد المراجعين أو الحسابات؟**
الخطة المجانية من Supabase تكفي بسهولة لعيادة كاملة (قاعدة بيانات حتى 500 ميجابايت ومستخدمين غير محدودين تقريبًا ضمن الاستخدام المعتاد).
